# 仕様書: データ記録と解析仕様 (Data Recording & Analysis Spec)

## 1. 概要
本ドキュメントは、Auto Mode（自動測定）および Sweep（連続回転）における、カメラ画像の保存、メタデータ（時刻・角度）の記録、および事後解析・動画変換に関する厳密な仕様を定義する。

光学測定装置としての信頼性を担保するため、ソフトウェア制御に起因する「時間の揺らぎ（ジッタ）」や「コマ落ち（ドロップフレーム）」が、測定結果（グラフ）や動画の再生時間に悪影響を与えない設計とする。

## 2. タイムスタンプの完全同期記録 (CSVロギング)

### 2.1 背景と課題
PCからのソフトウェアトリガーでカメラを制御する都合上、フレームの取得間隔は厳密な等間隔にはならず、数ミリ秒〜数十ミリ秒の揺らぎ（ジッタ）が生じる。これを無視して「一定間隔で撮影された」と仮定して解析を行うと、光強度のカーブが歪む原因となる。

### 2.2 解決策（実装済み）
画像をマルチページTIFFに直書き保存する特急レーンの処理と完全に同期して、以下の情報を **CSVファイル等のテキストログとして並行記録** する。

- **記録項目 (例):**
  - `Frame_Index`: 画像のインデックス番号 (0, 1, 2...)
  - `Frame_Timestamp_ms`: フレーム保存時刻（UNIXエポックタイムms）
  - `Angle_deg_nearest`: フレーム時刻に最も近い角度サンプル値（近傍観測値）
  - `Angle_Sample_Timestamp_ms`: 角度サンプルを取得した時刻（UNIXエポックタイムms）
  - `Angle_Age_ms`: `Frame_Timestamp_ms - Angle_Sample_Timestamp_ms`（角度情報の鮮度）

> **Note:** 本システムはハードウェアトリガー同期ではないため、角度値は frame-exact な真値ではなく近傍観測値として扱う。

### 2.3 保存先の分離

保存生成物は `outputDirectory` 直下を汚さないように分離して保存する。

- スナップショット: `outputDirectory/snapshots/`
- 録画: `outputDirectory/videos/`

これにより、測定ごとの出力をまとめて管理しやすくし、`outputDirectory` 直下のファイル衝突を避ける。

### 2.4 録画の開始・停止ログ

録画時は、API境界とデバイス境界の双方にログを残す。

- 開始: `record start requested` → `Recording save requested` → `Recording target path` → `Recording started`
- 停止: `Recording stopped`

録画停止時は、キャプチャスレッドが writer を閉じた直後に書き込もうとして `NoneType` 参照になる競合を防ぐため、writer の参照をロックで保護する。

### 2.5 終了時の判定

録画停止直後に `Error writing frame to TIFF/CSV` が出ても、必ずしも保存失敗とは限らない。停止と書き込みが同時に走った結果、最後の1フレームが落ちただけの可能性がある。

判定の優先順位は次のとおり。

1. `Recording started` が出ているか。
2. `Recording stopped` が出ているか。
3. `Error writing frame to TIFF/CSV` が停止直後の1回だけか。
4. 実ファイル（TIFF/CSV）が `videos/` に残っているか。

この条件を満たす場合、測定データは保存済みとみなしてよい。

## 3. 解析時のデータ取り扱いポリシー

- **強度の算出:** 人間の視覚向けである「グレースケール変換（重み付けやガンマ補正）」は一切使用せず、16-bit RAWデータの対象ピクセルの「総和（単純加算）」を光強度として扱う。これにより、サンプルの複屈折による色の変化に影響されない正確なカウントを保証する。
- **時間軸 (X軸) の構築:** 解析用のPythonスクリプト等は、動画(MP4)のフレームレートに依存せず、**必ず上記 2. で記録した CSV の `Frame_Timestamp_ms` をグラフの横軸として使用する**。
- **角度情報の扱い:** `Angle_deg_nearest` は補助メタデータであり、厳密同期角度としては扱わない。必要に応じて `Angle_Age_ms` の閾値でフィルタする。

## 4. MP4動画変換とドロップフレーム補完仕様 (Video Conversion Spec)

### 4.1 背景と課題
録画したマルチページTIFF画像をプレビュー・共有用にMP4（固定フレームレート規格）へ変換する際、単純な平均FPSを割り当てると、PCの処理落ちやUSB混雑でコマ落ちが発生していた区間が「早送り（詰まる）」になってしまい、現実の現象やSweep角度と時間軸がズレてしまう。

### 4.2 解決策: 埋め草補完（Drop-frame Interpolation）
録画停止後、設定（`autoConvertMp4: true`）に応じてバックグラウンドスレッド（貨物レーン）が非同期でTIFFをMP4へ変換する際、CSVのタイムスタンプを参照しながら以下の処理を行う。

1. **基準タイムライン**: ターゲットFPS = **30.0 FPS**（1フレーム約 **33.33 ms**）。
2. **時間差分の判定**: フレーム $k$ と $k+1$ の実際のタイムスタンプ差分 $\Delta t = t_{k+1} - t_k$ を計算する。
3. **埋め草挿入**: $\Delta t > 33.33 \text{ ms}$（＝コマ落ちした）場合、その空白時間を埋めるように、**直前のフレーム $k$ の画像を必要な枚数分リピートして動画内に挿入（水増し）する**。
4. **安全上限**: 長時間の一時停止等によるファイル肥大化を防ぐため、1区間あたりの補完上限を **最大 10 秒（300フレーム）** に制限する。
5. **CSV欠損時のフォールバック**: CSVが存在しない場合は、コマ落ち補完なし（一定 30 FPS）で安全に通常変換する。

**結果:**
コマ落ちが発生した瞬間は動画が一瞬フリーズしたように見えるが、**動画の総再生時間は現実の測定時間と完全に一致**し、角度走査と完全に同期した正確な記録動画となる。

### 4.3 メモリ保護と画像処理
*   **ストリーミング読み込み**: 巨大なマルチページTIFFでもメモリ（RAM）を圧迫しないよう、`tifffile.TiffFile` で1ページずつ順次読み込んで即座に MP4 へ書き出す。
*   **階調スケーリング（フリッカー防止）**: 16-bit画像（uint16）は固定スケーリング（ビット深度に基づくビットシフト等）により表示用 8-bit（uint8）へ変換し、フレームごとの明滅を防止する。
*   **カラー処理**: カラーカメラの場合は Bayer パターン（RGGB等）を OpenCV で BGR にデモザイクし、モノクロの場合は 3 チャンネル BGR に複製して出力する。
*   **コーデック**: クロスプラットフォーム互換性の高い `mp4v` (MPEG-4 Part 2) を採用。

### 4.4 設定連動とフェイルセーフ
*   `autoConvertMp4: true` の場合のみ変換を非同期実行。
*   `keepRawTiff: false` の場合、MP4変換が**正常に完了した場合のみ**元 TIFF を削除。変換エラー時は元 TIFF を 100% 保護し、不完全な MP4 のみ削除する。

### 4.5 進捗通知とUI連携
*   バックエンドは `GET /camera/video_conversion_status` により進捗率（`progress_percent`）およびステータスを提供。
*   フロントエンドは `sonner` トースト内に `shadcn/ui` の `Progress` コンポーネントを配置し、変換完了までリアルタイムに進捗を表示する。
