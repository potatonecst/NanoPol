# 仕様書: 自動測定アーキテクチャと制御仕様 (Auto Measurement Spec)

本ドキュメントは、ナノ粒子の偏光散乱光測定における「自動測定（Auto Mode）」を実現するための中核アーキテクチャ、制御フロー、およびデータ処理のポリシーを定義する。

## 1. アーキテクチャの基本方針（責務の分割）

自動測定では、「1つのサンプルに対して条件（ファイバの向き等）を変えて最大4回測定する」というワークフローが存在する。
システムの複雑化（God Objectの発生）を防ぐため、この管理を **Session Manager (UI層)** と **Measurement Manager (制御層)** の2階層に完全に分離する。

### 1.1 UI構成と用語の定義

ユーザー体験の直感性を高めるため、旧来の「State 0/A/B」という表現を廃止し、以下の3つのフェーズ（Phase）としてワークフローを定義する。

| フェーズ名 (UI表示) | 役割 | 識別子 (`autoPhase`) |
| :--- | :--- | :--- |
| **Session Management** | サンプルの新規作成、または過去の履歴（日付指定・Browse）からの再開 | `select_session` |
| **Category Selection** | 測定対象（Left-Front等）の選択と進捗確認 | `select_category` |
| **Measurement Execution** | 物理パラメータ入力、アライメント、および本番測定の実行 | `measuring` |

#### レイアウト構成 (`AutoView.tsx`)
`ManualView` の設計を踏襲しつつ、解析機能を強化したレイアウトを採用する。
*   **左側操作パネル (動的)**: 現在のフェーズに応じて操作UIを切り替える。
    *   **一貫したナビゲーション**: 「戻る」や「終了」などの前のフェーズへ戻るアクションは、常にパネル上部の**左側**に配置する。
    *   **コンテキスト表示**: パネル右側には、現在アクティブなサンプル名（`FolderOpen` アイコン付き）と選択中のカテゴリを常時表示し、操作対象を明確にする。
*   **右側ビューパネル (固定/Resizable)**:
    *   **上段: CameraPanel**: 映像プレビュー、ROI操作、リアルタイム輝度（Sum/Max）表示。
    *   **下段: GraphPanel**: `recharts` を使用し、測定中の散乱強度プロファイルをリアルタイムにプロットする。
    *   **分割**: `shadcn/ui` の `ResizablePanelGroup` (垂直分割) を使用し、映像とグラフの比率を調整可能とする。

### 1.2 Session Manager (UI ＆ ワークフロー層)
*   **責務**: 「実験ノート」としての進行管理とユーザーへの指示。
*   **管理対象**:
    *   `outputDirectory` (ユーザー設定) の配下、`AutoMeasurementData/<日付>/<サンプル名>/settings.json` の読み書き（測定履歴の永続化）。
*   **セッション開始のロジック**:
    *   **日付選択 (Date Picker)**: `shadcn/ui` の `Popover` と `Calendar` を使用。今日以外の日付も選択可能とし、過去の実験データのスキャンに対応する。
    *   **新規作成の保存先固定 (Safety Rule)**: カレンダーでどの日付を選択していても、**`[New Sample]` による新規作成は必ず「実行した当日の日付フォルダ」に対して行われる**。過去の日付フォルダに新しいサンプルが書き込まれることは決してない。
    *   **自動採番のスキャン範囲**: 新規作成時の自動採番（Sample_N）も、常に **「今日の日付フォルダ」** をスキャンして重複しない最小の連番を決定する。
    *   **フォルダブラウズ (Browse)**: OS標準のフォルダ選択ダイアログを介して、任意の場所にある既存セッションをロード可能とする。
    *   **履歴表示 (Session Table)**: `shadcn/ui` の `Table` コンポーネントを使用。サンプル名、作成時刻、測定進捗 (例: 2/4) を一覧表示し、再開ボタン（Resume）でロード可能とする。
    *   **データのロード**: 過去の `settings.json` を指定することで、ROI設定や完了ステータスを引き継いで再開できる。
*   **測定の自由選択と非破壊的やり直し (Redo)**:
    *   4つの測定条件（例：Left-Front, Left-Rear, Right-Front, Right-Rear）は**順不同**で選択・実行可能とする。
    *   **非破壊ルール**: 一度実行した条件を再度選択して「やり直し」を求めた場合、過去のデータを上書き・削除してはならない。必ず新しいIDを発行し、履歴に追記すること。

*   **完了・警告状態の判定 (UI表示・最新ステータス追従)**:
    *   各カテゴリーの選択ボタンに、現在の測定進捗とデータの品質を表すステータスアイコンを表示する。
    *   **最新ステータス採用の原則**:
        *   進捗マークは、過去の履歴全体ではなく **「そのカテゴリーに対する【最新（Last）の測定データ】のステータス」** を反映する。これにより、すでに成功（緑）しているカテゴリで再度測定を行い、そこで飽和（オレンジ）が発生した場合は、最新の不良データに追従してオレンジの警告表示へ自動で上書きされる。
    *   **アイコンおよび境界色の出し分け**:
        *   **未測定 (`"none"`)**: 通常カード表示（枠線ハイライトなし、ステータスアイコンなし）。
        *   **正常完了 (`"completed"`)**: 薄いグリーン枠（`border-green-500/30 bg-green-500/[0.01]`）および **緑色のチェックマーク** (`CheckCircle2`) を表示。
        *   **飽和警告あり完了 (`"saturated"`)**: 薄いオレンジ枠（`border-amber-500/30 bg-amber-500/[0.01]`）および **オレンジ色の「！」警告マーク (AlertCircle)** を表示。データ自体は生成されてディスクに存在しているため完了扱い（次のステップに進むことは可能）とするが、アライメントや露光の再調整が強く推奨される不良データであることを明示する。
    *   履歴が `status: "cancelled"` (ユーザー中断) または `status: "failed"` (エラー失敗) しかない場合は、未測定 (`"none"`) とみなしてアイコンを消去し、再試行を促す。
*   **タイムスタンプの記録**:
    *   `settings.json` には、Measurement Manager が本番測定（Step & Shoot）を開始・終了した時刻を `timestamp_start` および `timestamp_end` として記録する。
*   **動作**: 次の測定の準備（Measurement Execution フェーズ）が整ったら、保存先ディレクトリを確定させ、設定値（ROI、角度リスト等）を添えて `Measurement Manager` に1回分の測定を委譲する。

### 1.3 Measurement Manager (ハードウェア制御層)
*   **責務**: 渡された条件と保存先パスに従い、**1回分の自動測定（Pre-Scan または Step & Shoot）をノーミスで完遂すること**。
*   **完了後の遷移**: 本番測定が正常終了(`succeeded`)した場合、直ちに履歴を再取得し、カテゴリ選択画面へ自動的に遷移することで、ユーザーが次の測定をスムーズに開始できるようにする。
*   **手動操作の介入 (Manual Remote)**:
    *   測定の準備段階（アライメントや飽和確認）において、画面を切り替えずにステージを操作できるよう、ポップオーバー形式の「Manual Remote（ジョイスティック・アイコン）」を提供する。
    *   **機能**: 絶対角度入力による移動、および指定ステップ（0.1°, 1°, 5°）でのジョグ操作、機械的原点復帰（Home）、および緊急停止（Stop）をサポートする。
    *   **安全設計**: 移動実行中はUIをロックし、常に現在の角度を高精度に表示する。
*   **管理対象**:
    *   測定セッションの内部ステート（`Idle`, `PreScanning`, `Measuring`, `Paused`, `Finished`）。
    *   ステージ移動とカメラ撮影のミリ秒単位の同期制御。
    *   `DataSaver` を通じた CSV・画像・ROIメタデータの保存。
*   **独立性**: この層は「今がサンプルの何回目の測定か」を一切関知しない。与えられたタスクをこなし、結果（成功・失敗・飽和による中断）を上位に返すのみである。
*   **リアルタイムフィードバック (Graph)**:
    *   測定実行中、進捗イベント（Progress API）に含まれる最新の角度と輝度データを `recharts` で描画される `GraphPanel` に流し込み、リアルタイムでプロットを更新する。

## 2. データ処理と保存のポリシー（生データ主義）

定量的な物理測定の信頼性を担保するため、カメラから取得した画像データは、PCに到達した時点の**真のRAWデータ（無加工）**として保持・計算・保存する。

*   **スケーリングの禁止**:
    *   8-bitで受信したデータを、内部処理の都合で 16-bit（0-65535）に掛け算して引き伸ばすような処理は行わない。
*   **型の維持と保存**:
    *   カメラから `uint8` (8-bit) の Numpy 配列が渡された場合は、そのまま `uint8` として扱い、保存モジュールは 8-bit TIFF を生成する。
    *   将来 10-bit 等のカメラから `uint16` の配列が渡された場合は、そのまま 16-bit TIFF を生成する。
*   **ROI輝度計算**:
    *   計算（Sum, Max）は、データの型に関わらず生のピクセル値を単純加算（Sum）または最大値取得（Max）することで行う。
*   **リアルタイムフィードバック**:
    *   `CameraPanel` 表示中、バックグラウンドで ROI 内の `Sum/Max` を定期的に算出し UI に反映させることで、ユーザーによる手動での飽和確認を支援する。

## 3. Pre-Scan と オートセンタリングのアルゴリズム

Pre-Scan の目的は、波長板回転に伴う微小なプロファイル変動を考慮し、全角度で最も信頼できる「最適な1箇所」にROIを**固定（ロック）**することである。本番測定と同じ「Step & Shoot」制御を利用して実行される。

### 3.1 実行手順 (Pre-Scan)
1.  **粗いスキャン**: ユーザーが手動で合わせたROIを初期値とし、ステージを粗い間隔（例：15度〜22.5度）で1周回し、複数枚の画像を撮影する。
    *   **証拠の保存 (Fail-safe)**: 本番測定と同様、撮影した画像は一時保存し、終了後にマルチページTIFFに統合する。光強度データも撮影ごとに **`prescan/attempt_X.csv`** に逐次追記保存する。これにより、成否にかかわらず全ての試行を後から安全に検証できる。
    *   **リアルタイムグラフ**: スキャン実行中、初期ROIに基づいた輝度変化をリアルタイムでプロットし、信号の健全性を目視確認可能にする。
2.  **ドリフト防止の重心計算**: 各画像に対し、探索範囲を広げず**「設定された初期ROI枠内と完全に同じ範囲（マージンなし）」**のみを対象に重心を算出する。
    *   **非反復（One-shot）計算**: 探索範囲を絞っているため、反復法による過剰なノイズ追従（微小振動）を避け、**1回のみの計算**で高速かつ確実に中心を決定する。これにより隣接粒子への「歩き出し（ドリフト）」を完全に防ぐ。
3.  **重み付き平均による確定**:
    *   **コントラストチェック（シグナル有無の判定）**: 全画像の中で最も明るかった「Max Sum」と、最も暗かった「Min Sum」を比較する。差が十分にない（例：`(Max - Min) / Max < 0.1`）場合は、偏光によるサインカーブが存在せず「ただのノイズ（平坦）」であるとみなし、全画像を却下して直ちに「アライメント失敗（NG）」とする。
    *   **ダイナミックな足切り（暗所の除外）**: 上記のコントラストチェックをパスした場合、「Max Sum」の一定割合（例: `Max Sum * 0.2` 等）を下回る暗い画像（消光位の谷）は、ノイズに引っ張られた不正確な座標になるため計算から除外する。
    *   **平均の算出**: 除外されずに生き残った有効な画像の「仮の中心座標」に対し、その画像の「Sum輝度」を重みとして**重み付き平均**を計算し、最も明るく信頼性の高い座標に収束させる。
4.  **ROIのロック**: 算出された最終座標にROIを完全に固定する。以降の本番測定（Step & Shoot）ではROIを一切動かさない。
5.  **履歴の記録**: 各試行の開始・終了時刻や成否は、枝番フォルダ内の `measurement_details.json` の `prescan_history` に配列として全て記録する。

### 3.2 Step & Shoot ループ (Measuring)
ロックされたROIを使用し、以下のループを実行する。
1. **Move**: 次の角度へステージを移動させる (`move_absolute`)。
   *   **ポーリング遅延対策（即時ビジー化）**: コマンド送信直後、監視タスクのポーリング遅延（静止監視周期 1.0秒）による完了判定のすり抜けを防止するため、プログラム側で即座に `app_state.is_busy = True` を強制設定し、確実に移動完了待ちに入ります。
2. **Wait**: ステージの `is_busy` が `False` になるまで待機し、さらに **0.3秒間の物理的待機** を設ける（慣性振動の減衰およびコントローラの内部処理完了待ち）。
3. **Shoot**: カメラで画像を1フレーム取得する（`take_snapshot`）。
4. **Process & Save (Individual & Incremental)**:
   - 取得した画像から固定ROI of Sum / Max / Center輝度 / 重心座標(cx,cy) / Drift を計算する。
   - **フェイルセーフな画像保存**: 測定中のクラッシュによるデータ全損を防ぐため、1枚ずつ独立したファイルとして一時フォルダ (`images/`) に保存する。
   - **フェイルセーフな数値保存 (Incremental CSV)**: 1点測定するごとに、その結果を即座に **`[測定ID].csv`** (例: `1_Left_Front_001.csv`) に追記し、ファイルを閉じる。これにより、万が一途中で停止してもそれまでのデータがディスクに保護される。
   - **ファイル名の順序保証**: 小数点以下4桁を含むゼロ埋め形式（例: `angle_0045.5000.tif`）を使用し、OS上でのソート順を保証する。
   - 解析結果（角度、時刻、ROI輝度、画像パス）をメモリバッファに追記する。
5. **Next**: 角度リストが終了するまで 1 に戻る。

### 3.3 後処理 (Post-Processing) とクリーンアップ
全ループ完了、またはユーザーによってキャンセルされた場合、以下の処理を実行する。
1. **画像統合**: 撮影された個別の一時画像を、1つのマルチページTIFFファイルに統合する（キャンセル時はスキップ）。
2. **自動原点復帰**: ケーブルのねじれ防止と次回スループット向上のため、ハードウェア機能（`stage.home()`）を用いてステージを 0度（原点）に自動復帰させる。
   *   **Homing前の静止待機保護**: 測定がエラー等で異常終了した直後など、ステージがまだ物理的に移動中である場合に Homing コマンドが重複送信されて `NG`（ビジーエラー）になるのを防ぐため、`stage.home()` を送る前に `app_state.is_busy` を確認し、ビジーであれば最大15秒間、ステージの完全な静止を待ってから Homing を実行します。
3. **履歴記録**:
   - `measurement_details.json` および `settings.json` に、最終ステータス、開始・終了時刻、エラーメッセージ、オートセンタリング前後の座標比較を記録する。
   - **飽和検知時のステータス保存**: 測定中に一度でも飽和した角度が検出された場合（`len(saturated_angles) > 0`）は、物理的に正常終了（succeeded）した場合であっても、最終ステータスを `"completed"` ではなく **`"saturated"`** に変更して保存する。
4. **クリーンアップ**: TIFF統合が成功した場合のみ、一時画像フォルダを削除する。キャンセルの場合は一時画像を保持する。

## 4. 異常系のハンドリングとフェイルセーフ

### 4.1 飽和の動的判定と非破壊的ハンドリング
*   **動的閾値**: 飽和とみなすピクセル値の閾値は、接続されているカメラの有効ビット深度（`camera.input_bpp`）に依存して動的に決定する（8-bitなら255、10-bitなら1023）。ダイナミックレンジを最大限活用するため、マージンは設けない。
*   **非破壊的エラーハンドリング (止めない設計)**:
    *   本番測定中に飽和を検知した場合でも、システムは「強制停止 (Abort)」を行わず、そのまま指定された全角度の測定を完了させる。
    *   これは、意図的な白飛びを許容する実験や、後からのデータ救済（飽和した角度のデータをマスクしてフィッティングする等）を可能にするためである。
    *   **UIフィードバック (測定進行中)**: 進行中のプログレスバーを警告色（オレンジ）に変化させ、飽和した角度のリストをリアルタイムに表示することで、実験者に素早く気付きを与え、手動でのキャンセルを促す。
    *   **UIフィードバック (測定完了後)**: 測定完了後、通常時であれば緑色の「Completed」表示となるが、スキャン中に一度でも飽和が検出されていた場合は、進捗ステータスを **`"saturated"`** とし、オレンジ色の警告バッジおよび詳細メッセージ（飽和が検知された角度）を画面上に残し続け、警告する。

### 4.2 アライメントと飽和の分離
*   **両方OK**: 測定開始ボタンが有効になる。
*   **自動開始トグル (Auto-start after Pre-Scan)**:
    *   利便性向上のため、Pre-Scan 完了後に自動で本番測定を開始するオプションを用意する。
    *   **カウントダウン**: 自動開始前に 3 秒間の猶予期間を設け、カウントダウン UI を表示する。この間、ユーザーは `[Cancel]` ボタンで自動開始を阻止できる。
    *   **リスク提示**: 15度間隔の Pre-Scan では「ステップ間のピーク角度」での飽和を検知できないリスクがある。このリスクは専門家であるユーザーの判断に委ねるものとし、トグルの近傍に警告を表示する。
    *   **判断材料の提供**: Pre-Scan 実行中、その時点での最大輝度（Max 255 等）を UI 上に大きく表示し、ユーザーがカウントダウン中に測定を強行するか中止するかを目視で判断できるようにする。
*   **Pre-Scan中の飽和検知と本番移行制限**:
    *   Pre-scan 実行中に一度でも飽和（Saturation）を検知した場合、Pre-scan 終了時のステータスは `success`（緑）ではなく **`"saturated"` (オレンジ)** に遷移する。
    *   **警告の永続化と本番開始時の自動クリーンアップ**: スキャン終了後、進捗表示から警告を消去せず、**オレンジ色の `Saturated` バッジ**（英語表記 `Saturated`）および詳細な警告メッセージ（日本語）をアライメントカード内に残し続ける。ただし、ユーザーが本番測定を開始（START MEASUREMENT）した瞬間、このPre-Scanの完了ステータスおよび警告表示は自動的に `"idle"` (未実施状態) へクリアされ、本番測定中の進行プログレス上に表示されるリアルタイムの飽和警告情報（角度リストなど）との表示・干渉を防ぐ。
    *   **本番開始の許可と抑止**: 警告が出た状態でも本番測定の開始自体はロックしない（ユーザーがその設定で強行することを許可する）が、自動開始トグル（Auto-start）が ON であっても自動移行は強制キャンセルされ、カウントダウンなしでユーザーの確認操作（手動での測定開始ボタン押下）を必ず求める仕様にする。
*   **飽和OK ＆ アライメントNG**:
    ノイズ等で重心計算が収束しなかったケース。特例として **強制開始（Force Start）** ボタンを表示する。ユーザーが手動でROIを合わせた後、このボタンを押すことで、システムは「飽和していないことだけを確認」し、重心のズレは自己責任として測定を強行できる。

### 4.3 ROIサイズのバリデーション (将来の拡張)
*   手動調整時には 1x1 のROIを許可するが、本番測定（Auto Mode）開始時には「サイズ 3 以上」を必須とするバリデーションを設ける。
*   **理由**: サイズ 1 では周囲のピクセル情報がないため、第 3 節で定義した「重み付き平均による重心計算」が数学的に成立せず、アライメントの自動補正が行えないため。

## 5. UIコンポーネント設計（CameraPanelへの統合）

### 5.1 レイヤー構造の分離
カメラ映像のズーム（拡大・縮小）とUI要素の表示を両立させるため、DOMのレイヤーを以下のように分離する。
*   **画像＆ROI枠レイヤー**: `transform: scale()` などの影響を直接受けるレイヤー。カメラ映像（MJPEG）の上に、SVG 等で描画したROI枠を重ねる。これにより、画像をズームした際にROI枠も自動的に追従して拡大される。
*   **フローティング情報レイヤー（ミニテーブル）**: ズームの影響を受けない親コンテナ直下に絶対配置（`absolute`）するレイヤー。

### 5.2 ROIの基本操作と削除
*   **追加 (作成)**: `Ctrl + クリック`（または `Cmd + クリック`）で、クリック位置を中心に新規ROIを作成する。
*   **移動・リサイズ**: カメラ映像上でのドラッグ操作により直感的に行う。右下のハンドルをドラッグすることでサイズ変更が可能。
*   **削除操作**: 
    *   キーボード操作: `Alt + クリック`（または `Option + クリック`）で対象のROIを削除する。
    *   UI操作: フローティングパネル（ミニテーブル）内のゴミ箱アイコンクリックでも削除可能。


### 5.3 マウスイベントの競合回避
`CameraPanel` には「パン（平行移動）」機能が存在するため、これとROI操作が競合しないように厳密なイベント管理を行う。
*   ユーザーがROI枠を操作した際は、必ず `event.stopPropagation()` を呼び出し、親要素へのイベント伝播を停止する。
*   これにより、ROIを操作しようとして意図せず画像全体がパンしてしまうUXの低下を完全に防ぐ。

### 5.4 GraphPanel の統合
測定中のデータ視認性を確保するため、右側パネルを上下に分割して `GraphPanel` を配置する。
*   **配置**: `CameraPanel` の直下に配置。
*   **分割制御**: `shadcn/ui` の `ResizablePanel` により、ライブ映像とグラフの表示領域をユーザーが動的に変更可能とする。
