# 08. 自動測定データ構造リファレンス (Auto Measurement Data Guide)

このドキュメントは、自動測定（Auto Mode）によって生成されるデータの物理的な構造、ファイル形式、および `settings.json` の技術詳細を定義する実装リファレンスである。

## 1. 物理ディレクトリ構造

バックエンドの `DataSaver` モジュールは、以下のルールに従ってフォルダを生成する。

```text
{outputDirectory} / AutoMeasurementData / {YYYYMMDD} / {SampleName} /
```

### 1.1 階層の定義
*   **`outputDirectory`**: ユーザーが設定画面で指定した任意のディレクトリ。
*   **`AutoMeasurementData`**: 本システム専用の固定名トップフォルダ。
*   **`{YYYYMMDD}`**: 測定日の日付フォルダ（例: `20260605`）。
*   **`{SampleName}`**: サンプルのセッションフォルダ（例: `Sample_1`）。この中にそのサンプルの全データが格納される。

## 2. セッション管理ファイル (`settings.json`)

サンプルのルート直下に配置され、測定の全履歴と進捗を保持する。

### 2.1 スキーマ定義
| キー | 型 | 説明 | 例 |
| :--- | :--- | :--- | :--- |
| `app_version` | string | データ構造のバージョン | `"0.1.0"` |
| `sample_name` | string | サンプル名 | `"Sample_1"` |
| `created_at` | string | セッション開始時刻 (ISO 8601 UTC) | `"2026-06-05T10:00:00Z"` |
| `measurements` | array | 測定履歴のリスト。要素は後述の「測定エントリ」 | `[]` |

### 2.2 測定エントリ (`measurements` 内の要素)
測定が実行されるたびに、以下の形式のオブジェクトが配列の末尾に追加される。

| キー | 型 | 説明 |
| :--- | :--- | :--- |
| `id` | string | 枝番付きのユニークID（例: `Left_Front_001`）。フォルダ名と一致する。 |
| `step_category`| string | 測定のカテゴリ名（例: `Left_Front`）。 |
| `status` | string | 実行結果。`completed`, `aborted`, `failed` のいずれか。 |
| `timestamp_start`| string | 測定開始時刻。 |
| `timestamp_end` | string | 測定終了時刻。 |
| `folder_path` | string | この測定データの物理パス（絶対パス）。 |

## 3. 枝番（ブランチ）生成ルール

同じカテゴリでの再測定時、`DataSaver` は以下のアルゴリズムで重複を回避する。

1.  カテゴリ名（例: `Left_Front`）に `_` を付与する。
2.  その後に 3桁の連番（`001`, `002`...）を付加する。
3.  そのフォルダ名が物理的に存在しない最小の番号を確定し、フォルダを作成する。

## 4. 保存データの物理仕様 (Data Formats)

計測の信頼性と解析の正確性を担保するため、以下のデータ保存ポリシーを採用しています。

### 4.1 画像データ (`images.tif`)
*   **フォーマット**: マルチページ TIFF (Tagged Image File Format)
*   **生データ主義 (Bit Depth)**:
    *   カメラから取得されたビット深度を、**一切のスケーリング（掛け算）なし**でそのまま保存します。
    *   **8-bit カメラ接続時**: `uint8` (0-255) の NumPy 配列として受信し、そのまま 8-bit TIFF として書き出します。
    *   **16-bit カメラ接続時**: `uint16` (0-65535) として受信し、そのまま 16-bit TIFF として書き出します。
*   **理由**: 解析時にソフトウェア側で値を 16-bit に引き伸ばしてしまうと、真の飽和値（255等）が不明瞭になり、物理量としての正確な比較ができなくなるためです。

### 4.2 数値データ (`data.csv`)
*   **エンコーディング**: UTF-8 (BOMなし)
*   **記録項目**: タイムスタンプ、ステージ角度、ROI内の Sum / Max 輝度、画像インデックス。
*   **精度**: ステージ角度は小数点以下 4桁まで記録し、マイクロステップ駆動の分解能を保持します。

## 5. エラーレスポンス（API境界）

セッション管理 API が返す例外と、その発生理由は以下の通り。

*   **HTTP 400 (Bad Request)**:
    *   `outputDirectory` が未設定または空文字。
*   **HTTP 404 (Not Found)**:
    *   指定されたパスに `settings.json` が存在しない。
*   **HTTP 500 (Internal Server Error)**:
    *   `settings.json` のパース失敗（JSON形式が不正）。
    *   ファイルシステムへの書き込み権限エラー。
